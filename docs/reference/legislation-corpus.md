# Legislation corpus — Riigi Teataja XML, catalogue, reference vocabulary

Since 2026-09-05 (Ruling G) every statute the system reads comes from the official
Riigi Teataja consolidated-text XML, copied byte-identically into the repo and
rendered deterministically. No hand-pasted fragments remain. This page documents the
layout, the catalogue schema, the provision reference vocabulary and its bijection to
the Riigi Teataja element ids, how to add an act, and what `sd validate` checks.

## Layout

```
data/sources/legislation/
  catalogue.json                 generated by `sd corpus ingest`; never hand-edited
  ee/en/<globaalID>.akt          English translation (RT V), byte-identical copy
  ee/et/<globaalID>.akt          Estonian original (RT I), byte-identical copy
data/statutes/<act_slug>/
  statute.yaml                   selection spec: which catalogue entry, which provisions
  statute.rendered.txt           the declared provisions rendered (English); generated,
                                 drift-checked by `sd validate`, regenerated with --write-rendered
  oracle/text_term.json          term catalogue; anchors cite <act_slug>/<eId>
  oracle/term_rule.json          rules; law_references cite <act_slug>/<eId>
src/statute_decider/legislation/
  riigiteataja.py                XML parser, RT-id <-> eId bijection, rendering (stdlib xml.etree)
  catalogue.py                   CatalogueEntry / Catalogue models, load/save, slugify
  corpus.py                      Corpus: ingest, ingest_dir, check, load(global_id)
  references.py                  parse/validate <act_slug>/<eId>, display renderer
```

Current contents: 7 acts × {et, en} = 14 files (schema `tyviseadus_1_10.02.2010`):
Building Code, Civil Service Act, Family Law Act, Land Tax Act, Law of Obligations
Act, Personal Data Protection Act, Public Information Act (catalogue only, no case).

## The input is the official text: the act, or its smallest enclosing unit

`statute_text: file` (every committed condition) loads the act named by the statute's
`statute.yaml` and hands the prompt the **whole act** when its token estimate
(`ceil(chars / 4)`) fits `max_statute_tokens` (experiment setting, default 100 000);
otherwise the **smallest official structural unit** — part, chapter, division,
subdivision, as the XML divides the act — that encloses every declared provision,
rendered by the same renderer with the act header, a `Structural unit: …` breadcrumb
and every heading and number as in the text (Ruling H, 2026-09-06, ADR 0005;
`legislation/units.py`). In this corpus only the Law of Obligations Act (~316k tokens)
drops below the act: to `part_1__chp_2__dvs_4`, "Part 1 › Chapter 2 Contract ›
Subchapter 4 Distance Contracts" (§§ 52–62, ~13k tokens). `sd statute-input
--candidates` prints the choice and every candidate per act.
The node value / `row.statute_input` (also on every ledger line, in `meta`) records
`{act, global_id, sha256, unit: {kind, eid, display}, declared_provisions, method,
chars, tokens_estimate, max_tokens}`; rows written before 2026-09-06 carry the older
`statute_source` key. Structural units are addressed by their path eId
(`part_1__chp_2__dvs_4`) because level-local numbers restart inside each parent.
`statute_text: slice` renders only the declared provisions — the ablation "official
text vs declared provisions"; nothing committed uses it yet. Both are registered in
`runner/matrix.py`; the `statute_markup` / `markup_term` capability cells are
implemented by this package (XML parsing; provision resolver).

Rendering rules (`riigiteataja.Act.render_full` / `render_slice`): act title header;
part / chapter / division headings; `§ N. Heading`; subsections `(n)`, points `n)`
from the official `<kuvatavNr>` display numbers; `<sup>` → Unicode superscripts
(`(1¹)`, `4³)`); `<reavahetus/>` → newline; inline amendment markers
`[RT I, … – entry into force …]` kept by default (`strip_markers=True` drops them);
repealed provisions keep their `[Repealed – …]` line; annex PDFs (base64) skipped;
footnotes rendered at the end.

## `statute.yaml` — selection spec

```yaml
statute_id: land_tax_act            # = act_slug
kind: statute_text
title: Land Tax Act § 11            # display title kept from before
jurisdiction: EE
source:
  catalogue: ee                     # directory under data/sources/legislation/
  global_id: '505012026005'         # the English consolidated text
  # language: et                    # optional override: read the counterpart instead
scope: full_act                     # documentation of Ruling 2; the only value
provisions:                         # the eIds the rules / catalogue were written against
- sec_11
notes: ...
```

## Catalogue schema (`catalogue.json`)

Top level: `generated_by`, `note`, `entries[]`. One entry per consolidated text:

| field | meaning |
|---|---|
| `jurisdiction` | `ee` |
| `language` | `en` (publication series RT V = translation) or `et` (RT I = original) |
| `source` | `riigiteataja` |
| `act_group_id` | `<terviktekstiGrupiID>` of the file. Informational — it is **not** shared between the EN and ET files of one act |
| `global_id` | `<globaalID>` of this consolidated text; the key |
| `title` | `aktinimi/nimi/pealkiri` |
| `act_slug` | English act slug = the statute id vocabulary (`land_tax_act`); ET files take it from the EN counterpart, else a slug of their own title |
| `document_type`, `text_type` | `seadus`, `terviktekst` |
| `adopted_on`, `entry_into_force` | the act's adoption date and original entry into force |
| `in_force_from`, `in_force_until` | this redaction's validity window; `null` when open |
| `original_publication` | the act's first publication (`RT I, 05.03.2015, 1`); identical in both languages |
| `publication` | this text's own reference (`RT V, 10.08.2026, 2`) |
| `schema_name` | `<skeemiNimi>` |
| `source_url` | official URL it was fetched from (`--url`) |
| `file`, `sha256`, `size_bytes` | the byte-identical copy and its hash |
| `downloaded_at` | source file mtime (UTC) |
| `ingested_at` | when `sd corpus ingest` ran |
| `counterparts` | `global_id`s of the same act in the other language |

Counterparts are linked by the natural key (`adopted_on`, `original_publication`): the
XML's `terviktekstiGrupiID` turned out to differ between the EN and ET files of the
same act, so it is stored but not used for linking.

## Reference vocabulary

One provision key everywhere we write: **`<act_slug>/<eId>`**, an Akoma Ntoso-style
eId. RT element ids are never stored; `riigiteataja.rt_id_to_eid` / `eid_to_rt_id`
recompute them at lookup and are a bijection (round-trip tested on every id in all 14
files). Display form from one function, `references.display_reference`
("Land Tax Act § 11 (5) 1)"; without the title "§ 11 (5) 1)"). A section whose only
subsection is unnumbered in the XML (§ 44 Building Code, § 15 Civil Service Act, § 4
Personal Data Protection Act) is `sec_N__subsec_1` in the key and displays without
the `(1)`: `§ 44 1)`.

| Riigi Teataja element / id | eId | display |
|---|---|---|
| `<paragrahv id="para11">` | `sec_11` | § 11 |
| `<loige id="para11lg1">` | `sec_11__subsec_1` | § 11 (1) |
| `<loige id="para11lg1b1">` (`loigeNr ylaIndeks="1"`) | `sec_11__subsec_1_1` | § 11 (1¹) |
| `<alampunkt id="para11lg5p1">` | `sec_11__subsec_5__point_1` | § 11 (5) 1) |
| `<alampunkt id="para53lg4p4b1">` | `sec_53__subsec_4__point_4_1` | § 53 (4) 4¹) |
| `<paragrahv id="para11b1">` (§ 11¹) | `sec_11_1` | § 11¹ |
| `<osa id="osa1">` (EN files: `o1`) | `part_1` | Part 1 |
| `<peatykk id="ptk2">` | `chp_2` | Chapter 2 |
| `<jagu id="jg1">` | `dvs_1` | Division 1 |
| `<jaotis id="jaotis1">` / `<alljaotis id="alljaotis1">` | `subdvs_1` / `subsubdvs_1` | Subdivision 1 / Sub-subdivision 1 |

Grammar: `level_number[_superscript]` parts joined by `__`; provision levels
`sec > subsec > point` must appear as a prefix in that order; structural levels stand
alone. Any deeper element type met in a future file raises at parse time — extend
`references.PROVISION_LEVELS` deliberately.

`clause_id` = the key; `clause_title` = the display form (checked by `sd validate`);
qualifiers the display form cannot carry ("first sentence") live in the anchor `note`.
Traces (`outcome_trace`) print display forms only.

## Adding an act

1. Download the consolidated text XML (`.akt`) for the English translation and the
   Estonian original from riigiteataja.ee (the "XML" link on the act page).
2. `sd corpus ingest <file.akt> --url <official url>` for each file (English first so the
   Estonian file inherits the slug), or put `ee-<lang>-<act>.txt` files (line 1 URL,
   line 2 file name) next to `et/` and `en/` directories and run `sd corpus ingest-dir <dir>`.
3. `sd corpus check` — re-hashes every file; missing/changed files fail; validity
   windows that differ within a group or have ended, and provision sets that differ
   between languages, are reported as `info` only.
4. For a case: create `data/statutes/<act_slug>/statute.yaml` (above), the oracle JSONs
   with `<act_slug>/<eId>` anchors, then `sd validate --write-rendered` to generate
   `statute.rendered.txt`; commit both.

## What `sd validate` checks

For every statute directory: `statute.yaml` parses and its `statute_id` matches the
directory and the catalogue entry's `act_slug`; the act loads from the corpus; every
`provisions` eId resolves in the XML; every `clause_id` in `text_term.json` and
`term_rule.json` parses, cites this act and resolves; every `clause_title` equals the
corpus display form; `statute.rendered.txt` equals the deterministic slice of the
declared provisions (drift fails; `--write-rendered` regenerates). The unit tests
(`tests/test_legislation.py`) round-trip every RT id in all 14 files through the
bijection, check the slices (`land_tax_act/sec_11` yields § 11 with all subsections;
`sec_11__subsec_5__point_1` yields exactly that clause) and the metadata.

## Known facts about the current files (2026-09-05)

- The English texts are translations of a given redaction; EN and ET validity windows
  differ for the Law of Obligations Act (en 2026-06-30 – 2026-08-31; et 2026-09-01 –
  2026-12-31). At every section a rule cites, the EN and ET provision sets are identical.
- Provision sets differ elsewhere within some groups (e.g. 16/33 eIds only in en/et for
  the Law of Obligations Act) — sections present in one redaction only; `sd corpus
  check` lists them as `info`.
- Sizes of the full acts fed to prompts: see `state/es/phd3-jurix-xml-corpus-2026-09-05.md`
  in the ES; the Law of Obligations Act renders to ~1.26 M characters (~300 k tokens).
